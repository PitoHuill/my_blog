# Astro 双栏个人博客设计

## 目标

创建一个部署到 GitHub Pages 的静态个人博客。整体参考深色、克制、学术个人主页的气质，但不复制参考站内容。默认保留宽屏双栏阅读体验，同时在手机端转为单栏；支持日间与夜间主题，并记住访客选择。

## 技术边界

- 使用 Astro 静态站点与 Markdown/MDX 内容集合。
- 使用 GitHub Actions 构建并发布至 GitHub Pages。
- 不需要自建服务端或数据库。
- 评论可选用 Giscus（GitHub Discussions）；未配置时不展示评论区。

## 站点结构

顶部导航固定为四项：`首页`、`文章`、`项目`、`关于`。不提供“归档”和“标签”的顶部入口；它们仅作为文章页和文章列表中的辅助筛选/关联信息。

```text
/
├── 首页：个人侧栏、精选文章、Now 状态、最新文章、项目摘要
├── /posts：文章列表与页内筛选
├── /posts/[slug]：文章正文、目录、元数据、相关推荐、上一篇/下一篇
├── /projects：项目列表
├── /projects/[slug]：项目详情
└── /about：简介、经历、联系方式、链接
```

## 首页布局

在 `>= 960px` 的视口中，内容容器最大宽度为 1120px；左栏 250–270px，右栏占其余空间，栏间距 32px。导航位于页面顶部，并在滚动时保持可访问。

左栏从上至下：

1. 个人卡片：头像、姓名、一句简介。
2. 数据统计：文章、项目、论文/成果三项。
3. 外部链接：GitHub、邮箱、RSS；有学术主页时再添加。
4. 可选的精选论文/成果列表。没有内容时不渲染占位卡片。

右栏从上至下：

1. 精选文章：仅一篇，带 `FEATURED` 微型标签、标题、日期、标签和两行摘要。
2. Now 状态：一句正在关注或正在做的事，并链接到 `/about#now`。
3. 最新文章：默认展示 3–5 篇；每篇是可点击文章卡片。
4. 项目摘要：展示 1–2 个代表项目并链接到项目页。

小于 768px 时，导航收窄但保留四个入口；左栏移至文章列表之前，并把统计与链接改为两列/单列自然换行。内容不使用横向滚动。

## 视觉规范

- 气质：简洁、沉静、偏阅读与研究记录；留白优先于装饰。
- 字体：标题使用衬线字体（如 `Noto Serif SC` 或系统衬线栈）；正文、元数据、标签使用无衬线字体。
- 夜间默认颜色：背景 `#19191d`，卡片 `#222227`，边框 `#36363d`，正文暖白 `#f2efe7`，强调青绿 `#7eaf9d`。
- 日间颜色：背景 `#f7f5f0`，卡片白色，边框 `#dedbd3`，正文 `#282721`，强调青绿 `#327562`。
- 颜色应以 CSS 语义变量实现，所有组件只引用变量，避免在组件内写死深浅主题颜色。
- 卡片为 1px 细边框、轻微圆角；悬停仅改变边框/背景或上移 1–2px，避免大幅阴影与动画。
- 文章标题清晰优先；摘要最多 2–3 行，超出时截断。

## 主题切换

导航右侧使用无文字的图标按钮：夜间显示月亮，日间显示太阳；按钮必须有 `aria-label` 和悬浮提示。初次访问遵循系统偏好；用户点击后将偏好保存在 `localStorage`，以后优先使用该偏好。切换主题不应出现明显闪烁。

## 组件划分

```text
src/components/
├── SiteHeader.astro       # 品牌、四项导航、主题图标按钮
├── ThemeToggle.astro      # 系统偏好、localStorage 与图标状态
├── ProfileCard.astro      # 头像、姓名、简介
├── StatGrid.astro         # 三项统计
├── ExternalLinks.astro    # GitHub、邮箱、RSS
├── FeaturedPost.astro     # 首页唯一精选文章
├── NowCard.astro          # 当前状态
├── PostCard.astro         # 最新文章和文章列表复用
├── ProjectCard.astro      # 首页和项目列表复用
├── ArticleMeta.astro      # 日期、阅读时长、标签
├── TableOfContents.astro  # 长文目录
├── Pagination.astro       # 文章分页
└── Footer.astro           # 版权、RSS、最后构建时间
```

`BaseLayout.astro` 负责主题变量、页面容器、页头和页脚；首页仅组合组件，不包含文章内容查询逻辑。内容查询集中在 `src/lib/content.ts`，便于文章、项目和统计数字复用。

## 内容模型

文章内容集合字段：`title`、`description`、`pubDate`、`updatedDate`（可选）、`tags`、`featured`、`draft`、`cover`（可选）。项目集合字段：`title`、`description`、`year`、`status`、`repository`（可选）、`demo`（可选）、`featured`。草稿不参与生产构建。

首页统计基于已发布内容在构建时计算；论文/成果数来自站点配置字段，避免误把博客文章计入其中。

## 文章阅读页

文章页显示标题、日期、阅读时长、标签和正文。桌面端目录可随正文滚动保持可见；移动端目录折叠。正文结束后依次显示相关推荐、上一篇/下一篇、可选 Giscus 评论。标签点击进入 `/posts?tag=...`，因此标签仍可用，但不进入顶栏导航。

## 增强能力

- RSS：自动生成并在侧栏和页脚提供入口。
- 本地搜索：使用 Pagefind，在文章数量增长后启用。
- Sitemap 与 Open Graph：每篇文章有规范 URL、描述、分享标题和可选封面。
- 无障碍：键盘可访问，主题按钮有可读标签，颜色对比符合 WCAG AA，图片使用替代文本。
- 性能：优先静态生成，图片使用 Astro 图片优化，避免不必要客户端 JavaScript。

## 发布与验证

GitHub Actions 在推送默认分支时执行依赖安装、静态构建并发布 `dist/` 至 GitHub Pages。部署前需要在 Astro 配置中设置仓库对应的 `site` 和 `base`。

验收条件：

1. 首页桌面端为双栏，移动端为单栏，无横向溢出。
2. 顶部只显示“首页、文章、项目、关于”和主题图标按钮。
3. 日夜主题可切换、刷新后保持，首次访问遵循系统偏好。
4. 首页含精选文章、Now 状态、最新文章和项目摘要。
5. 文章可由 Markdown 发布，草稿不会部署。
6. GitHub Pages 能从默认分支自动构建和发布。
